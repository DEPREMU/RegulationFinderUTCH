Emanuel coordinates with another team for at least **60 independently authored answerable questions**. A user-designated 60-question set has now been evaluated, but its CSV does not identify the authoring team; confirmation of the required other-team provenance is pending. Three supplied synthetic test questions are only smoke fixtures. Preserve non-identifying team/source references and collection/version records. Have accepted article IDs reviewed against the authorized source. Record ambiguous questions and adjudication before freezing. Collect out-of-scope questions separately; they do not count toward the answerable requirement.

1. Karen and Zaid establish topic labels and disjoint training/development splits. Check duplicate IDs, normalized duplicate text, near paraphrases and leakage manually as well as through validation.
2. Fit learned preprocessing/vocabulary and classifier only on training. Use development questions to select smoothing changes, ranking settings and confidence thresholds. `uv run --frozen regulation-finder calibrate --steps 11` reports a grid of topic-probability and lexical thresholds using only development examples; it deliberately does not select a setting or inspect out-of-scope/final evaluation examples. The Week 3 workflow uses `scripts/select_development_settings.py` to apply its documented objective to that development-only grid. Do not choose settings from test results.
3. The user-designated Week 3 questions and accepted IDs were frozen before final testing. Their file hash, dataset/model identifiers, dependency lock, settings and available provenance are in `artifacts/training/week3-independent-evaluation-freeze.json`. The CSV does not identify its authoring team.
4. The frozen set was run once with `scripts/evaluate_independent_questions.py`; the hash-checked JSON output is `artifacts/training/week3-independent-evaluation.json`. The result is 32/60 top-three hits (53.3%), with 19 answerable abstentions. Use `--split development` only during tuning. `calibrate` performs a development-only sweep but does not select settings automatically.
5. Report measured counts/denominators, failure examples and limitations. Treat subsequent changes as a new experiment requiring fresh untouched testing; do not silently retune on test failures.

**Top-three hit rate** = answerable questions with any accepted article among the first three *displayed* articles / **all eligible answerable questions**. An abstention is a miss. One accepted match is enough; multiple accepted IDs never multiply hits. Report H/N and percentage. With zero eligible questions, rate is null, not zero or success.

Also report answerable abstention count/N and out-of-scope abstention count/M, plus out-of-scope false returns M minus abstentions. These metrics never remove difficult/abstained answerable examples from the headline denominator. The JSON includes per-question displayed IDs and hit flags for audit.
